> reviewer's scratch folder and are not kept; the line numbers are as of the commit it names.

## Ranked findings

Each entry gives the issue, the evidence, the change I propose, its risk and its effort (S/M/L).

### 1. The dev server shows `concept/` to anyone who changes the case of the URL, and listens on the whole LAN
- **Evidence:** `tools/dev-server.mjs:31-32`: `file.startsWith(path.join(ROOT, 'concept'))`. The same check is in
  `tests/lib/server.mjs:18`. macOS (APFS) is case-insensitive by default, so `/Concept/<file>` and `/CONCEPT/<file>`
  open the real files. I simulated the check: `/concept/…` is refused, `/Concept/…` and `/CONCEPT/…` are not, and
  the files exist. `server.listen(PORT)` (`dev-server.mjs:54`) binds every interface, so anyone on the same Wi-Fi can
  fetch them. The test server binds `127.0.0.1` and is local only. Two more gaps: `startsWith(ROOT)` also accepts a
  sibling folder such as `…/argonisos-assets`, and `.git/`, `.assets-git/` and `incoming assets/` are served too.
- **Change:** take `rel = path.relative(ROOT, file)` and refuse it if it starts with `..`, or if its first segment,
  lower-cased, is `concept`, `.git`, `.assets-git` or `incoming assets`. Put the rule in one helper used by both
  servers. Bind the dev server to `127.0.0.1`, with a `--host` flag for testing on a phone.
- **Risk:** none for the game. The dev asset browser reads `assets/models/pack/all`, not `incoming assets`.
  **Effort:** S.

### 2. The CI workflow, the lean deploy and the build stamp were never merged, yet three docs say they are live
- **Evidence:** `.github/workflows/` holds only `pages.yml`. `ci.yml` (lint, cycles, knip, fingerprint, and a refusal
  of PRs whose base isn't `main`) exists only in commit 98209e4 / 8b217a2 (17 Oct), on the branches `ci-workflows`
  and `project-review`, and neither branch is merged into `dev`. Docs that claim it is live: CLAUDE.md:69
  ("GitHub Actions runs it on every PR (`.github/workflows/ci.yml`)"), CLAUDE.md:10 ("CI refuses any other base"),
  README.md:24-25 and docs/review/REPORT.md:61-64.
  The live `pages.yml` copies the whole checkout (`rsync -a … ./ _site/`, excluding only `.git`, `.github`, `_site`,
  `_assets` and `concept`). That means `tests/`, `tools/` (including `tools/assets/manifest.json`, which lists the
  licensed packs, and `backup.mjs` with the private repo's URL), `docs/`, `.claude/`, `CLAUDE.md` and `dev/` are all
  public on Pages. The deploy never writes the build stamp either, so `<meta name="build" content="">`
  (`index.html:6`) stays empty and the title screen shows no build (`src/ui/title.js:8,27`), although README.md:26
  says it does.
- **Change:** cherry-pick 98209e4 onto a branch from `dev`, then reconcile its `pages.yml` with the current one. Keep
  the private-assets checkout and the `hero.glb` guard from 6b83780, and add the whitelist copy (`index.html src vendor
  assets legacy`) and the stamp `sed` from 98209e4. Add `npm run lint:css` to `ci.yml`, since `check-css.mjs` came
  later. Then make `main` require the check (branch protection).
- **Risk:** the whitelist must still include everything the live game fetches. `dev/` is deliberately left out.
  Check with one deploy. **Effort:** S–M.

### 3. One renamed item, piece or skill makes every existing save unbootable
- **Evidence:** `src/game/save.js:40`: `def: g.ITEMS[f.id].food` throws when a food id no longer exists.
  `save.js:51` → `build.load` (`src/build/build.js:608`) → `place` (`build.js:416-418`): `PIECE[id]` is undefined, so
  `def.hp` throws. `save.js:39`: `P.stats.skills = st.skills || …` replaces the whole skills object, so a skill added
  after the save was made is missing, and `skillK`/`damageK`/`drain` (`src/player/stats.js:84,90,91`) throw on
  `this.skills[s].level` every frame. `load(g)` runs inside `createGame` (`src/game/game.js:208`) with no try/catch:
  an exception stops the boot, and it happens again on every visit until the player clears site data. A save left
  half-loaded would then be overwritten by the next autosave.
  `src/game/inventory.js:68` already filters unknown ids; the other loaders don't.
- **Change:** filter unknown ids in `stats.food`, `build.load`, the drops in `pickups.load` and grave slots. Merge the
  skills onto the defaults (`for (const k in st.skills) if (P.stats.skills[k]) Object.assign(P.stats.skills[k], st.skills[k])`).
  Wrap `load` in try/catch: on failure, copy the raw save to `argonisos.world.v1.bak`, start fresh, and show a toast.
  Add a `loop` step that loads a save with an unknown item, piece and skill.
- **Risk:** low. **Effort:** S.

### 4. Loading a save can give a new building piece the id of one that already stands
- **Evidence:** `src/build/build.js:418` gives each piece `uid: opts.uid ?? 'pc' + this.seq++`, and
  `build.js:608` sets `this.seq = this.placed.length + 1` after loading. Example: place pc0…pc4, take down pc0 and
  pc1, save and load. Then seq is 4, and the next piece becomes `pc4`, the same id as a piece still standing. The uid
  keys the colliders (`colliders.addGroup` first removes the group of that key: `src/world/colliders.js:7`), the
  ground cut (`setCut`) and the grass clearing (`clearGrass`). The new piece takes over the old one's colliders and
  ground shaping, and taking either down strips both.
- **Change:** `this.seq = 1 + Math.max(-1, ...this.placed.map((p) => +p.uid.slice(2) || 0))`.
- **Risk:** none. **Effort:** S.

### 5. `biomeWeights` returns a shared object that every `heightAt` call overwrites
- **Evidence:** `src/world/gen.js:41-43` defaults `out` to a module-level `_w`, and `rawHeight(x, z, w = biomeWeights(x, z))`
  (`gen.js:214`, the same in `meadowPath:340` and `groundColor:360`) means every `heightAt` rewrites `_w`.
  `src/game/game.js:167-169` keeps `bw = biomeWeights(P)` across nine `heightAt` calls at other places and reads
  `bw.y`, `bw.v` and `bw.p` afterwards. It is right only because the last call happens to be `heightAt(P.x, P.z)`.
  `src/main.js:201→210` keeps `bw` across `veg/structures/build.tallestNear` and `heightAt`. Moving one line breaks
  the ambience mix or the woods' haze without any error.
- **Change:** give `rawHeight`, `meadowPath` and `groundColor` a private scratch object as their default, and let
  callers that hold the result pass their own `out`.
- **Risk:** none (the world fingerprint proves it). **Effort:** S.

### 7. `harvest.js` has its own small audio engine that bypasses the mixer
- **Evidence:** `src/game/harvest.js:134-168` builds its own brown-noise buffer (`brown`, a copy of `sound.js:39`
  `makeNoise(…, brown)`), its own distance and pan (`heard`, a copy of `sound.js:118` `spatial`), `logThud` and a
  `Rumble` class. It reaches the audio graph through `THUNDER.out()` and `THUNDER.ctx()` (`sound.js:414`, a hook
  named for thunder). Its sounds therefore skip the effects bus and the indoor muffling, multiply `SETTINGS.sfx` by
  hand (`harvest.js:142`), and never reach `AUDIO.log`, so `tests/suites/audio.mjs` can't see them.
- **Change:** move `logThud` into `SFX`, and put a `rumble()` handle (start, set, stop) on `sfxBus` in `sound.js`.
  Harvest then calls `sound('logThud', …)` and `rumble(…)`. This also removes `THUNDER.ctx/out`, unless lightning
  still needs them.
- **Risk:** the logs' loudness changes slightly (the bus and the compressor). Listen once, and run the audio and
  harvest suites. **Effort:** S–M.

### 10. Tests rely on fixed waits; only one suite polls
- **Evidence:** the harness has no polling helper (`tests/lib/harness.mjs:18,55`: `wait(ms)` only). Only
  `combat.mjs:14` defines an rAF-based `until`. Fixed waits per suite (`t.wait` plus in-page `setTimeout(r, N)`):
  movement 20 + 4 (about 36 s of sleeping: 3000 ms ×3, 7500, 4000…), audio 27 + 1, features 8, creatures 6 + 7,
  build-houses 8 in-page, olympos 2 + 6, vegetation 6 + 1, harvest 2 + 4. Each wait is either too long (slow) or,
  on a loaded machine, too short (flaky).
- **Change:** add `until(f, ms)`, `frames(n)` and `sleep(ms)` to the snippet prelude `H` and a `t.until(code, ms)` on
  `Run`. Convert the waits one suite at a time, starting with movement and audio.
- **Risk:** low. **Effort:** M.

### 11. Some materials are created and disposed each time, against the "keep materials" hitch rule
- `game/trial.js:80-86` `skyBeam` makes two new `MeshBasicMaterial`s on every reveal and disposes them 4.8 s later,
  so the program is compiled again each time.
- `creatures/models.js:109,265` clones every material for each body, and `free()` (`models.js:23`) disposes them. When
  the last creature of a kind despawns, the program can be released and is compiled again at the next spawn, unless
  `warmUp` holds a copy.
- **Change:** pool these (share one beam material; keep creature clones per kind with the fader's program-key pattern).
- **Risk:** low. **Effort:** S–M. (The perf reviewer may measure this.)

### 13. `npm run check` misses things the project's rules depend on
- Madge's entries are `src/main.js` and `src/world/terrain-worker.js` only (`package.json` `cycles`). The dev pages
  (`src/dev/browser.js`, `src/dev/anim/main.js`) aren't checked. They have no cycles today: I checked.
- Nothing stops a licensed or private file from being committed (for example with `git add -f`, or after a
  `.gitignore` edit). Add a guard: `git ls-files concept 'incoming assets' 'assets/*/pack' '*.xlsx'` must be empty.
- The page snippets in the tests are strings, so ESLint, Knip and Madge are blind to them. Their
  `import('/src/…')` paths and named imports form an unchecked API. A move or rename (any of S1–S5) passes

  and `{ a, b } = await import(…)`, then check that the file and its exports exist.
- `tools/assets/manifest.json` is never parsed in CI; a `JSON.parse` step is enough.
- **Effort:** S. These would also have caught item 2's drift if CI ran.

### 14. Repo hygiene and `.gitignore`
- `Argonisos asset list.xlsx` sits at the root, untracked and **not ignored** (`git status` shows `??`). One `git add -A`
  would publish it to the public repo. Move it to `concept/` or `incoming assets/`, or add `/*.xlsx` to `.gitignore`.
- `tools/tmp/` is an empty leftover directory that nothing writes to. Remove it.
- `tests/reports/` (189 MB, ignored) holds one-off sheets from October that no script writes any more

  Legacy imports `.fbx.js` directly (`legacy/game.js:2705`), so keep the FBX copies legacy uses and drop the rest. If

### 15. Optional chaining on systems that always exist, and handlers chained by wrapping
- `g.sound?.(` appears 95 times, `g.build?.` 14, `g.acts?.` 13, `g.structures?.` 11, `g.map?.` 7 and `g.trial?.` 7.
  All of them are assigned in `createGame` (`game.js:41-60`) before the first update. If a system were wired wrong,
  the `?.` would silently do nothing instead of failing. `sound()` itself already guards (`sound.js:370`). The
  optional chaining is reasonable only in modules the dev sandbox loads without a game.
- Handlers are chained by wrapping the previous one (`game.js:49` `onDeath`, `owl.js:84` `onFirstItem`), so the order
  depends on construction order. A tiny `g.on(event, fn)` list would make it explicit.
- **Risk:** low. **Effort:** S (opportunistic).

### 16. Game events run on wall-clock timers, which a pause doesn't stop

  `save.js:50`. Pausing during them doesn't hold them: the map opens, or you respawn, under the pause menu.
- **Change:** keep a small game-time queue in `game.update` (`g.after(secs, fn)`), so the timers stop with the world.
- **Risk:** low. **Effort:** S.

## Tests: coverage gaps and speed

- **T1. Not covered by any suite:** dying, respawning, the grave and getting your things back (only the playtest bot
  does it); the character creator; saves with unknown or old ids (item 3); the piece-uid case (item 4); worn armour
  showing on the hero (`hero.wear`/`dress`); the patch notes and title flow beyond a screenshot.
- **T2. Speed:** besides item 10, many suites stream the world once for each step's teleport. Grouping steps by place
  (as `tests/lib/places.mjs` begins to) and polling `terrain.pending === 0` instead of sleeping would save the most.
  I didn't run the suites, so I have no per-suite timings: `results.json` had just been overwritten (item 14).
- **T3. A sites fingerprint in a quick suite** (before S1): in the page, hash each `structures.groups[i]` (vertex count
  and the sum of positions per material), `solids`, `tops`, `uses` and the colliders. Do the same for `propGeo`
  geometry per species and variant. This makes the `structures.js`/`trees.js` refactors safe without the slow visual
  suite, much as the world fingerprint does for the layout.
- **T4.** `world.mjs` runs in Node and is fast. The same Node approach could cover `Inventory`/`ITEMS` invariants (as
  `sort.mjs` does) and the save round-trip, with a fake `g`.
